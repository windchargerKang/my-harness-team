# Common Review

## 作用

这是 `review-skills` 的通用底座，用来统一评审时的默认关注点和输出习惯。

## 适用范围

适用于所有 review 场景，特别是当你还不确定要用哪一个专项 skill 时。

## 通用检查顺序

1. **安全性**：是否有数据破坏、越权、误删误改等风险。
2. **正确性**：行为是否符合预期，是否存在明显逻辑缺陷。
3. **影响范围**：是否会影响公共路径、多个模块或历史数据。
4. **可维护性**：实现是否清晰，后续是否容易误用或扩散风险。
5. **可验证性**：是否能通过测试、日志或可观察结果验证。

## 风险分级

- **严重问题**：可能导致数据错误、权限问题、线上故障或大范围回归。
- **警告问题**：存在潜在缺陷、边界不清或后续维护风险。
- **建议项**：可改善可读性、可维护性或评审体验，但不阻塞发布。

## 输出要求

- 保持简洁、事实化。
- 优先写清楚文件、行号、风险类型和建议动作。
- 避免空洞表扬和泛泛而谈。

## 与专项 skill 的关系

- `prepare-review`：负责整理变更摘要。
- `spring-architecture-review`：负责 Spring 分层与职责边界。
- `sql-risk-review`：负责 SQL 和数据风险。

当专项 skill 已经给出更具体规则时，以专项 skill 为准。
