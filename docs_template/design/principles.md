# Frontend Design Principles

## 目标

为 `harness-team` 流程中的前端变更提供统一的设计基线。

## 原则

### 1. 信息优先
页面首先要让用户看懂，再追求好看。

### 2. 层级清晰
标题、说明、主操作、辅助操作、状态提示必须有明确层级。

### 3. 状态完整
任何可交互页面都要考虑 loading、empty、error、success、permission denied。

### 4. 组件克制
优先使用成熟、稳定、常见的组件模式，不追求花哨特效。

### 5. 密度匹配场景
B 端偏高信息密度，C 端偏体验和节奏，不混用默认风格。

### 6. 响应式可用
从小屏到大屏都能正常工作，不能只在桌面端“看起来没坏”。

### 7. 可访问性默认达标
键盘可达、对比度合格、表单提示可读、交互反馈明确。

### 8. 允许合理偏离
模板是参考，不是枷锁。偏离可以，但要能解释。
